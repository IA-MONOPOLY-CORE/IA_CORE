# Roadmap 4.x Macro-Mission 04.2

## Native Security Generation Zero contract

Status: `DEVELOPMENT_ORIGIN_INERT`; this document contracts security learning
inside the existing `GOKV`, `DOOL` and `OCI` families. It does not create a
security fourth family, runtime, provider, permission grant or tenant reader.

## Direction

The active direction is:

- `SECURITY_IS_A_NATIVE_OPERATING_PLANE`;
- `SECURITY_BY_DESIGN_NOT_SECURITY_AS_AN_ADD_ON`;
- `DEFENSE_IN_DEPTH_OVER_SINGLE_PRODUCT_DEPENDENCE`;
- `AI_ASSISTS_SECURITY_DETERMINISTIC_CONTROLS_ENFORCE_IT`;
- `SECURITY_STRENGTH_MUST_BE_MEASURED_NOT_MARKETED`.

Security is materialized only as evidence-bound contracts and deterministic
guards. A green test is evidence of the tested boundary, not a claim that the
system is invulnerable or commercially superior.

## Family placement

| Family | G0 identity | Allowed learning | Explicit exclusions |
| --- | --- | --- | --- |
| GOKV | Defensive knowledge contract | Verified threat patterns, provenance, mitigations, validity and expiry | Secrets, raw tenant content, executable artifacts, automatic promotion |
| DOOL | Security control learning | Successful and failed controls, false positives, guard outcomes and bounded decisions | Model weights, runtime learning, cross-tenant raw sharing |
| OCI | Necessary-and-sufficient security composition | Fit by agent, tool, enterprise, domain, risk and hardware | Universal permission, runtime injection, provider calls |

All three identities are G0, `DEVELOPMENT_ORIGIN`, model-independent and inert.
They use the existing typed edge catalog and remain horizontally compatible.

## Inheritance

`EVERY_NEW_ENTITY_INHERITS_VALIDATED_DEFENSIVE_LEARNING` means that a future
entity may receive only validated, scoped, necessary and sufficient defensive
learning. It does not transfer secrets, plaintext enterprise content, private
prompts, chain-of-thought, raw tenant data or untrusted offensive material.

OCI must retain `NECESSARY_AND_SUFFICIENT_INHERITANCE`. Fit is evaluated against
the agent, tool, enterprise, domain, risk and hardware context. Absence of fit,
evidence or authorization fails closed; it never becomes a universal grant.

## Evidence and lifecycle

The graph is the canonical G0 contract. The current GOKV vault remains
unchanged: no security item, event, pack, metric, promotion or vault write is
introduced by this materialization. Future candidates must use the existing
lifecycle and explicit selection; Owner direction alone is not promotion.

Success and failure are both reusable development evidence. They remain
classified, redacted and bounded before any future inheritance decision.

## Domain parity

`DOMAIN_MODULES_HAVE_PARITY_NO_DOMAIN_HAS_INHERENT_PLATFORM_PRIVILEGE` is a
security invariant. Lotería may appear only as observed legacy/domain evidence;
it is not a privileged security module, platform pillar or preferred consumer.

## Boundaries

Runtime, execution, providers, external calls, tenant reads, raw secret reads,
payload activation, permission grants, automatic promotion, model training and
production exposure remain disabled. No offensive repository is downloaded,
cloned or executed in this mission.
