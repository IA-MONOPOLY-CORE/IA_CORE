## Direction before execution

Method Santi 3.0 treats the destination as separate from the current route.
The roadmap is the north, not a cage. A phase closes through a
`PHASE_COMPLETION_CONTRACT`, not by reaching a number or by accumulating files.
Direction retains irreducible human decisions: authority, policy, ownership,
trust, legal meaning, activation, external evidence and phase exit.

The method distinguishes:

- `METHOD_POLICY`: rules for deciding, sequencing, pausing and recovering work.
- `GOKV_LEARNING_LIFECYCLE`: the governed development-origin process for
  capture, assessment, storage, compilation and promotion.

The method can guide execution without becoming a promoted operational capability.

## Core method contracts

### Destination, route and completion

`DESTINATION != CURRENT_ROUTE`.

Every mission starts from an explicit destination and an entry contract. The
current route is allowed to change when evidence changes dependencies, provided
the route remains in phase scope, uses no new authority, is reversible and
testable, and preserves closed work. Completion means the phase contract is true
and the forbidden unknowns are not being hidden.

### Phase Execution Graph

Large phases are represented as blocks and conditional edges, not as a rigid
linear list. Each block declares objective, inputs, dependencies, stations,
dynamic station families, tests, rollback, outputs and postconditions. An edge
declares continue, recalculate, stop, reorder and human-decision conditions.

### Frontier Engineering

A frontier is not accepted as a wall until the method asks what makes it a
frontier. For each frontier record:

`RAW_FRONTIER_DISTANCE -> FRONTIER_ENGINEERING -> EFFECTIVE_TRUE_FRONTIER_DISTANCE`

Frontier Engineering separates apparent gaps, resolvable contract gaps,
conditional edges, external-evidence limits, emergent unknowns and true hard
human decisions. A frontier may dissolve through better provenance or a route
reorder, but it may not be bypassed by assumption.

### Frontier Dissolution Contract

A frontier can be dissolved only when:

1. the required evidence is named;
2. the evidence is allowed and obtained safely;
3. no new authority is inferred;
4. the same phase destination is preserved;
5. closed work remains valid;
6. the resulting condition is testable and reversible;
7. any human decision remains visible.

### Effective Block Size

Block size is determined by deterministic distance to the next meaningful
contract boundary, not by an arbitrary prompt length. A block may be split when
it crosses a sensitive frontier or merged when its surfaces share owner,
evidence and rollback. No block may hide a true hard frontier.

### Safe Operating Envelope Expansion

The operating envelope expands only by demonstrated evidence and explicit
authority. Source presence, a plan, a provider adapter, a sandbox artifact or a
successful documentary test does not mean runtime, execution, active agent,
network, deployment or operational write is open.

## Safe pause and route recalculation

`STOP_EXECUTION != CLOSE_MACRO_MISSION`.

The protocol is:

1. `SAFE_PAUSE`: stop the affected work, preserve green commits and freeze the
   product boundary.
2. `ROUTE_RECALCULATION_CHECKPOINT`: record expected route, new evidence and
   invalidated assumption.
3. `EMERGENT_FRONTIER_DETECTION`: classify the boundary.
4. `CONTINUATION_DIRECTIVE`: authorize the smallest same-destination route.
5. `RESUME_POINT`: resume from the last green station.
6. `GRAPH_REORDERING`: reorder only under the conditional edge contract.

Roadmap 3.2 is evidence of:

```text
APPARENT_FRONTIER
-> SAFE_PAUSE
-> ROUTE_RECALCULATION
-> CONTINUATION DIRECTIVE
-> SAME MACRO-MISSION
-> PASS
-> PUBLICATION
```

The event was a historical guard temporal-scope mismatch. The correction bound
the old guard to its own published checkpoint, preserved its allowlist and did
not create a 3.2 exception. This validates the pattern in this context; it does
not claim universal validation of every v3 technique.

## Mission control rules

- Preflight authority, branch, HEAD, remote, ahead/behind and working tree.
- Protect product code and current contracts until an explicit change exists.
- Use station-local work, evidence, tests, gate and commit.
- Evidence precedes closure claims.
- Test depth scales `FOCAL -> GROUP -> CANONICAL -> DEEP_HISTORICAL` by risk.
- Historical guards validate their own horizon.
- Preserve contract over UI or narrative inference.
- Use real diff over planned commit name and avoid giant commits.
- Revert only the invalid station; do not perform global rollback.
- Stop at a true hard frontier and return the decision to Direction.
- Push only after all gates, then fetch and verify exact alignment.
- Keep `PROMOTED_ONLY`, current-contract precedence and no fake autonomy.

## Project and creative integration

Method Santi 3.0 uses the Creative Intake framework to locate ideas without
forcing implementation. A project begins with a Project Genesis Pack so each
new project inherits method, authority, source of truth, gates, frontiers,
recovery, reporting and learning boundaries instead of rediscovering them.

## Metrics

The method defines a future metric contract for phase, blocks, stations,
frontiers, route recalculations, graph reorderings, Direction/Architect
interventions, retries, rollbacks, time deltas, closed surfaces and result. It
does not invent values that were not recorded. Operator-reported metrics are
append-only and are not reconstructed from chat history.
