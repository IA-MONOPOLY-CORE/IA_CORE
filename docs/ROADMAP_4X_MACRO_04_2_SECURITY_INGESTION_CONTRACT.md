# Roadmap 4.x Macro-Mission 04.2

## Future security knowledge ingestion contract

State: `FUTURE_CONCEPT_PRESERVED_NOT_SCHEDULED_NOT_IMPLEMENTED`.

`UNTRUSTED_SECURITY_REPOSITORIES_ARE_EVIDENCE_NOT_AUTHORITY` is the governing
rule. A source cannot become code, a dependency, an instruction or promoted
knowledge merely because it is security-related.

## Source confidence classes

Future ingestion must classify sources as official standards and taxonomies,
verified advisories, component security documentation, reviewed research,
known defensive repositories, untrusted offensive repositories, malware samples,
real incidents, internal learning and enterprise-specific evidence.

The class is provenance, not permission. Every class remains subject to scope,
license, integrity, confidentiality and human governance.

## Untrusted and offensive material

Before any future analysis, an untrusted or offensive source would require:

- immutable identity, hash, provenance and license;
- signature verification when available;
- risk classification and quarantine;
- static analysis and, only if separately authorized, isolated dynamic analysis;
- disposable filesystem and no production credentials or secrets;
- outbound network `DEFAULT_DENY` and authorized targets only;
- human approval where the risk class requires it;
- sanitized defensive extraction;
- reversible manual promotion with complete traceability;
- safe deletion and poisoning/contamination response.

No offensive artifact reaches production unsandboxed. No external security
corpus is auto-promoted. A future cyber range remains
`FUTURE_CONCEPT_PRESERVED_NOT_SCHEDULED_NOT_IMPLEMENTED`.

This mission does not clone repositories, install offensive tools, execute
exploits, analyze malware dynamically, contact external targets or create
productive attack capabilities.

## Defensive output only

When eventually authorized, ingestion may produce threat patterns, mitigations,
policies, guards, regression tests, detections, secure configurations,
containment playbooks, recovery procedures and reusable defensive knowledge.
It must not copy exploits or expose raw offensive artifacts as operational
instructions.

## Claim classification

Current repository observations are `OBSERVED` only when backed by local files or
tests. Architectural direction is `OWNER_DIRECTED` or `INFERRED`. Future
external corpus properties remain `EXTERNAL_EVIDENCE_REQUIRED`; unavailable
facts remain `UNKNOWN`.
