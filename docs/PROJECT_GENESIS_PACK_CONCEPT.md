# PROJECT GENESIS PACK

## Status

`PROJECT_GENESIS_PACK_DOCUMENTED_CONCEPT`

The Project Genesis Pack is a reusable starting contract for a new or existing
project. It prevents each project from rediscovering how to establish authority,
scope, testing and recovery. It is not automatic tooling, a runtime package,
an execution bundle or a product feature.

## Required contents

1. `METHOD` - active method version and preserved historical method lineage.
2. `AUTHORITY_MODEL` - Direction, Architect, operator and executor boundaries.
3. `SOURCE_OF_TRUTH` - repository, checkpoints, current contracts and precedence.
4. `PREFLIGHT` - root, branch, HEAD, remote, ahead/behind and clean-tree checks.
5. `MISSION_MODEL` - mission ID, type, mode, baseline, scope and forbidden actions.
6. `STATION_MODEL` - stations, inputs, outputs, gates and no-diff stations.
7. `GATE_MODEL` - authority, scope, evidence, test, diff, secret and frontier gates.
8. `FRONTIER_MODEL` - apparent, resolvable, conditional, external and true-hard rules.
9. `TEST_POLICY` - focal, group, canonical and deep historical selection.
10. `GIT_CHECKPOINT_POLICY` - station-local commits, real diff, no giant commit and publication verification.
11. `RECOVERY_MODEL` - safe pause, local rollback, route recalculation and resume point.
12. `REPORT_CONTRACT` - self-contained continuity report with exact final state.
13. `CREATIVE_INTAKE` - the eight-category placement framework and IDEA_RECORD.
14. `LEARNING_LIFECYCLE` - DOOL capture, validate, distill, assess, store, compile and promotion governance.
15. `METRICS` - block, station, frontier, intervention, retry and rollback contract.
16. `READINESS_MODEL` - completion contract, allowed unknowns, forbidden unknowns and next-phase entry.

## Initialization sequence

```text
SELECT_METHOD
  -> RECONSTRUCT_AUTHORITY
  -> RUN_PREFLIGHT
  -> DEFINE_DESTINATION_AND_COMPLETION_CONTRACT
  -> CENSUS_SURFACES
  -> BUILD_BLOCK_AND_FRONTIER_GRAPH
  -> DECLARE_TEST_AND_RECOVERY_POLICY
  -> START_ONLY_THE_AUTHORIZED_MISSION
```

The pack is a contract, not a permission slip. Product mutation, runtime,
providers, network, deployment, secrets, integrations or enterprise features
remain forbidden unless a separate mission explicitly authorizes them.

## Existing and future projects

For an existing project, the pack begins with continuity reconstruction and
preserves historical checkpoints. For a new project, it establishes the same
boundaries before implementation. In both cases, current contracts win over
conflicting historical notes, and future architecture remains distinct from
current capability.

## Readiness and recovery

The pack must make it possible to answer what is true before starting, what
would force a safe pause, how a route can be recalculated without changing the
destination, which commit is green, and what evidence is required to close the
phase. A project is not ready because the pack exists; it is ready only when its
readiness contract passes.
