# Roadmap 4.x Macro-Mission 06 - VERO Adjudication

## Decision

```text
CANDIDATE: VERO
DECISION: MERGE
TYPE: COMPOSITION_OF_EXISTING_CAPABILITIES
FOURTH_FUNCTIONAL_PILLAR: NOT_ADOPTED
IMPLEMENTATION: NOT_STARTED
VERO_G0: REJECTED_AS_A_NEW_RUNTIME; DEVELOPMENTAL_EVIDENCE_PROFILE_DEFERRED
CONFIDENCE: HIGH
```

VERO is a coherent responsibility, but the repository does not justify a new
service, store, endpoint, panel, tenant, or fourth execution pillar. Its useful
responsibilities are split between bounded P1 observation, Method Santi
direction, closure evidence, GOKV lifecycle, DOOL provenance and OCI inheritance
controls.

## Evidence adjudication

| VERO concept | Existing evidence | Adjudication |
| --- | --- | --- |
| Reality assertion and as-of state | P1 status schema, bounded metrics, protected memory/log envelopes | Keep as future contract vocabulary; do not create a parallel assertion store |
| Evidence source and provenance | GOKV capture/schema, DOOL provenance, commit/evidence ledgers | Existing owners remain canonical |
| Freshness and bounded observation | P1 status/metrics contracts and zero-read-on-deny tests | Extend contracts only in a future scoped mission |

| Intervention commitment | Method Santi contracts, validation basis and rollback evidence | Belongs to Method Santi, not VERO authority |
| Outcome assessment and causal ceiling | No complete material contract found | Real gap; defer until a bounded contract and owner are approved |
| Local/global separation | DOOL/OCI privacy and inheritance boundaries | Existing boundary is authoritative; VERO cannot transfer data globally |
| Measurement budget and anti-Goodhart | Method metrics and evidence limitations | Candidate method extension, not a runtime module |
| VERO.G0 development evidence | Closure gate runs and canonical evidence | Rejected as a new runtime; current evidence can support a future read-only profile |

## Ownership and boundaries

```text
METHOD_SANTI formulates intervention and evaluation criteria
SECURITY authorizes access and action boundaries
P1 contracts expose bounded observations
GOKV governs lifecycle and promotion decisions
DOOL preserves development-origin provenance
OCI controls inheritance and privacy
VERO vocabulary, if retained, describes evidence and outcome semantics
```

VERO must never decide, authorize, execute, expose, promote, or infer causal
certainty. It cannot convert forecasts into observations, rewrite baselines,
read raw logs or memory before authorization, or move private enterprise facts
into global learning.

## Minimum future G0

The smallest useful VERO.G0 is a documentary/read-only evidence profile over
existing development closure artifacts: `validation_basis`, pre-run claims,
observed test results, repairs, timestamps, freshness, limitations and causal
ceiling. It must not create a new store or runtime. Its entry condition is a
separate contract that defines retention, privacy and evidence provenance.

## Deferred responsibilities

Outcome contracts, intervention graphs, multi-horizon value semantics,
measurement budgets and enterprise reality assertions remain deferred. Their
absence is an explicit gap, not a reason to manufacture VERO infrastructure in
Macro 06.

## Name compatibility

`VERO` is retained as a conceptual label in the adjudication package because it
names verified reality and outcomes clearly. It is not a canonical module or
permission namespace in the current repository.
