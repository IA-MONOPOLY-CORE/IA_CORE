## 1. Verified adaptive execution feedback

Execution feedback is evidence about the route, not a promise about future
speed. A mission records the forecast before modification, the real clocks,
validation cost, failures, repairs, frontier discoveries, and final outcome.
Correlation may guide recalibration, but it must not be promoted to universal
causality or a guaranteed acceleration claim.

The method incorporates the following protocols:

```text
THREE_CLOCK_MISSION_METRICS_V1
PRE_LEVEL_B_HISTORICAL_IMPACT_GATE_V1
ESTIMATE_CALIBRATION_PROTOCOL_V1
FULL_REPORT_FIRST_PASS_POLICY_V1
INTERRUPTION_RECOVERY_EVIDENCE_PROTOCOL_V1
VALIDATION_COST_ACCOUNTING_V1
```

## 2. Three mission clocks

Every mission separates:

```text
FUNCTIONAL_PUBLICATION_TIME
DOCUMENTARY_CLOSURE_TIME
OPERATOR_VISIBLE_COMPLETION_TIME
```

Functional publication ends when the green functional checkpoint is remotely
verified. Documentary closure ends when evidence, metrics, ledger, and final
documentation are published and fetched. Operator-visible completion requires
external operator evidence and must not be invented from internal timestamps.

## 3. Historical Impact Gate before Level B

Before a global suite:

1. Freeze the changed-file manifest.
2. Discover exact and nominal references in tests and guards.
3. Identify all historical-context consumers.
4. Run the complete affected historical cohort.
5. Run guards for each affected roadmap checkpoint.
6. Run UI and method guards that inspect changed surfaces.
7. Repair checkpoint mappings nominally when evidence requires it.
8. Preserve every assertion and do not use broad globs.
9. Create the validation basis only after the cohort is green.

Historical tests validate their own checkpoint contract. Current tests validate
current truth. A historical bookkeeping mismatch is documented as such; a
productive regression is not relabeled as bookkeeping.

## 4. Estimate calibration

Each mission records central estimate, expected range, contingency ceiling,
assumptions, real duration, variance, relative error, range position, causes
of deviation, and one evidence-backed adjustment for the next forecast. A
faster result is not universally generalizable; a slower result is not hidden.

For Macro-Mission 04.5, the forecast is registered before edits:

```text
FORECAST_VERSION: PRE_EXECUTION_V1
ESTIMATE_CENTRAL_SECONDS: 8100
EXPECTED_RANGE_SECONDS: 6300-10800
CONTINGENCY_CEILING_SECONDS: 14400
```

## 5. Full report first pass

The first final response must contain the complete self-contained report,
including all files, commits, tests, failures, repairs, warnings, skips,
unknowns, protected surfaces, timings, quota evidence, Git state, and next
cursor. It must not use “main commits”, “selected files”, “among others”, or
“etc.” as a substitute for enumerating evidence.

## 6. Interruption recovery

If the host cuts out, the method does not assume pass or fail. It checks active
processes and Git state, classifies the interrupted attempt, resumes from the
last published checkpoint, repeats any validation without a demonstrable
result, separates wall-clock from active-time, and records unknown values as
`UNKNOWN`.

## 7. Validation cost accounting

Every Level B attempt records start, end, wall time, process time when
available, passed, failed, skipped, warnings, exit code, cause, repair, total
cost, percentage of mission time, and optimization opportunity. The method
does not add skips, delete assertions, widen guards, mock the unit under test,
or change production only to satisfy an unauthoritative historical snapshot.

## 8. Evidence boundaries

The method may record learning in GOKV, DOOL, or OCI only under their existing
governance. It cannot manufacture candidates, copy private logs, promote
automatically, activate OCI, call providers, or introduce tenant material.
