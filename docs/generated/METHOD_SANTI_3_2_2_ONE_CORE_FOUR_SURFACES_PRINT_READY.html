1. Method Santi 3.2.2

MISSION SCALE: optimize governed surface throughput, not prompt count or raw volume. A prompt may contain many coherent, verifiable, rollbackable stations.

BLOCK: complete important section. STATION: finished verifiable architectural piece. COMMIT: exact preservation of one approved station.

ONE_STATION_ONE_COMMIT and EVERY_COMMIT_IS_ACCOUNTABLE keep every station and repair traceable. A repair is explicit and receives its own commit.

2. Dynamic frontiers

Frontiers are reevaluated with current evidence. Continue when behavior is derivable; pause only for a genuinely new human decision, external fact, authority, or irreducible risk. Independent safe branches may continue while one branch is blocked.

FRONTIER_AT_MISSION_START
evidence -> owner -> contract -> remaining unknowns
FRONTIER_AT_TIME_OF_ARRIVAL -> route recalculation -> safe pause or next station

3. Learning and continuity

IA_CORE accumulates operational experience without changing model weights. GOKV preserves governed knowledge and provenance; DOOL preserves development-origin observations; OCI selects pertinent knowledge within resource, privacy, scope, and risk boundaries. Promotion is explicit and never automatic, with no artificial quota.

Every close produces a self-sufficient handoff containing state, decisions, contracts, evidence, unknowns, frontiers, commits, rollback point, protected boundaries, and next safe point. Relevant inheritance is sufficient, not indiscriminate.

4. Full report and publication

Operational prompts require one self-contained report by default: result, Git state, sources, contracts, failures, stations, commits, repairs, validation, learning, frontiers, limitations, remote state, and next recommendation.

5. ONE CORE, FOUR SURFACES

IA_CORE es un único sistema evolutivo con un solo núcleo canónico. Desde ese núcleo se expresan cuatro superficies adaptadas a entornos diferentes; no son cuatro productos independientes, codebases autónomas ni desarrollos desde cero.

  1. IA_CORE PLATFORM - portable platform on existing systems.
  2. IA_CORE OS DESKTOP/SERVER - future native desktop/server expression.
  3. IA_CORE MOBILE - future Android/iOS application or companion.
  4. IA_CORE MOBILE OS / MOBILE ENVIRONMENT - future native mobile expression.
IA_CORE CANONICAL CORE
        |
  PLATFORM HOSTED | OS DESKTOP/SERVER | MOBILE APP
                                      |
                                   MOBILE OS

The shared core governs identity, knowledge, GOKV/DOOL/OCI, memory, agents, permissions, contracts, evidence, observability, security, lifecycle, integration, and cumulative learning. Surface-specific UI, adapters, drivers, packaging, and runtime may evolve without forking central truth.

Principles: ONE_CORE_FOUR_SURFACES; NO_INDEPENDENT_PRODUCT_FORKS; SHARED_INTELLIGENCE_ENVIRONMENT_SPECIFIC_EXECUTION; PRESERVE_FUTURE_ARCHITECTURAL_OPTIONALITY; EARNED_IRREPLACEABILITY; HUMAN_AMPLIFICATION_WITH_SELECTIVE_SUBSTITUTION.

6. Boundaries and closure

The doctrine does not create an installable OS, mobile app, native terminal, provider connection, endpoint, integration, runtime, execution path, workforce, permission, or product payload. Future OS work must preserve kernel, drivers, security, essential services, and system stability.
